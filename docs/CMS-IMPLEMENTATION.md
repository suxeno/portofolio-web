# Sanity CMS implementation and operational plan

## Current status and boundaries

The user approved a controlled deployment to the existing production Worker. The deployed SSR version uses the Cloudflare adapter to read and validate public published Sanity data when rendering, with no private read token. Explicit unconfigured development mode uses local records; configured failures return an error rather than fallback. Dynamic home, archive and article routes can reflect content and slug changes without a code build. Sanity's CDN and the shared edge cache introduce propagation delay; there is no guarantee changes appear within 60 seconds.

The gateway sets browser `max-age=0` and shared edge `max-age=60` only for canonical anonymous successful HTML. Sensitive/noncanonical requests bypass it; errors and 404s are no-store. The approved production test observed MISS, HIT with the same inner-render identifier, EXPIRED after more than 60 seconds with a new identifier, and a subsequent HIT. Query, cookie, authorization, no-cache and HEAD bypass plus repeated 404 no-store were checked. The installed local Miniflare setup does not demonstrate cache hits, so its SSR tests explicitly bypass caching and the separate version-checked live probe in `scripts/cms-live-cache-probe.py` tests the platform behavior. The `X-Portfolio-Render` UUID is nonsecret and changes per eligible inner render; it is not a visitor ID. Main independently verified the live cache behavior and reviewed the focused SSR/cache regressions.

`/admin/` is prerendered hash-routed Studio, or setup-required without both public build identifiers. Sanity enforces editor permissions. Production Studio authentication and authenticated read/write/upload/publish worked in the user's Chrome session, without a CORS change. An independently operated GUI test published a disposable writing with `visible: false`, an inline body image, alt text and caption; direct API readback confirmed the saved values. The public home/archive excluded it and its article URL returned 404. The test document and asset were deleted through Studio and their absence verified by a raw dataset query. No existing editorial content was changed. Public pages retain Vue; Studio/React belong only to admin. No credential belongs in browser bundles.

## Architecture and trade-offs

Astro 7.4.7/Vue 3.5.45 uses the pinned Cloudflare adapter and static assets, with Sanity Studio using React and hash routing. The adapter uses passthrough images and disables sessions to avoid unneeded Images and KV bindings. Studio Portable Text supports headings, paragraphs, links, lists, quotes, code and image blocks with alt/caption; it is not a Medium clone. Article rendering escapes content and validates URLs and asset references. Fonts, decorative assets and presentation behavior remain code-managed. The separate signed rebuild webhook is legacy, inactive and not required by the SSR design; do not provision it as a workaround for unverified cache behavior.

## CI, publishing and gates

The local CI changes run baseline tests with public Sanity identifiers blank, then `CMS_PUBLISH=true bun scripts/ci-production-build.mjs` creates a configured production build and output integrity seal. `bun run check:deploy` validates the seal and generated `dist/server/wrangler.json`, then runs Wrangler dry-run; the seal is not a signature. The tested generated output is the only deployment target. CI deployment remains gated by tests and existing branch/event conditions; no further deployment is authorized by this document.

Content is public read-only to visitors and editor writes remain authenticated by Sanity. Code changes require a build and a separately approved deployment; published content changes require no rebuild, but upstream CDN lag and the edge cache prevent a timing guarantee. Never expose a GitHub PAT or Sanity write token in the public app or logs. The legacy `workers/cms-publish` implementation is inactive; provisioning or activation would need separate approval and is unnecessary for SSR.
